Independent-container public-resource profile: Y0--Y7
====================================================

Authorization and baseline
--------------------------

The user authorized sequential implementation and isolated validation of
Y0 through Y7 on 2026-09-20. The source starts at 9dffb41aefcd28870c60b7c04ffb32f78566ef0e
on codex/ckernel-periodic-profile. Only ordinary append-only publication to
that branch is allowed. Main, ckernel-m, the host kernel, existing containers,
and historical evidence are protected. No recurring automation is requested.

The default workload has private working directories, processes, FD tables,
address spaces and connections. Sharing a function or a pathname is not
sharing an object. A configured common backend is a candidate; contemporaneous
use, contention and causal interference are separate evidence levels.

Ordered implementation and validation
-------------------------------------

Y0: Remove private-object collectors from default admission and automatic
routing. Retain explicitly selected legacy extensions and their negative
tests. Split Maple context from allocator observation and verify actual
source disablement, BPF inventory and memory, not merely report filtering.

Y1: Introduce bounded, epoch-bound resource topology for cgroup ancestry,
filesystem/device, queue and CPU/NUMA placement. Never upgrade common
configuration to observed contention. Invalidate on restart, unregister,
migration, namespace changes or unproved object lifetime.

Y2: Deepen ancestor counter, selected allocator-node, physical-page supply
and reclaim coverage. Select bounded caches/nodes per session. Keep atomic
updates distinct from holder/waiter relations. Preserve native accounting.

Y3: Add selected ext4/JBD2 public transaction and allocation-state evidence
using private directories. Orphan behavior depends on filesystem features.
Shared read-only image/cache diagnosis is conditional on actual sharing.

Y4: Add bounded block queue/tag occupancy association, dirty throttling and
writeback pressure. Preserve submitter, billed owner and worker separately.
Do not identify the largest I/O producer as the unique blocker.

Y5: Add selected public qdisc/device queue admission and service evidence
for independent sockets. Bound packet/source associations; transformations,
lost attribution and device-internal causes remain explicitly unknown.

Y6: Relate CPU wait, quota, IRQ/softirq and selected background work. Hardware
PMU/SPE enhancement requires runtime capability and independent decoding
validation; optional unsupported hardware does not establish causal coverage.

Y7: Validate private-directory/container workflows against shared and
separate backends. Compare OFF, reduced survey and survey plus specialist.
Preserve all failed trials, independent truth and raw artifacts. Report
source/worker/background CPU, memory, target/bystander throughput and P99,
loss, coverage and periodic/queue/explanation delays separately.

Acceptance and exclusions
-------------------------

No stage passes merely because code or tests exist. Status separates
implementation, unit tests, build, VM runtime, coverage and measured cost.
Existing X0--X7 evidence is historical, not acceptance for changed code.
Tail latency remains record-only under the user's prototype authorization;
correctness, false attribution, cleanup and source budget guards still apply.

The bounded two-second specialist window and shared scheduling budget remain.
Idle sources must be disabled, not silently discarded after entering BPF.
No global hot-path owner map lock, unbounded object tracing or whole-machine
stack tracing may be introduced to discover shared resources.

Tests must include independent private objects with hardware/CPU competition,
same versus separate filesystem/device/queue/ancestor, object reuse,
registration changes, source storms, failure and cleanup. A lock fixture
checks the adapter; it cannot certify ordinary cross-container incidence.

The work does not implement automatic governance, kernel optimization, shadow
objects, host replacement or universal causality. Completion means the stated
bounded public-resource scope has reproducible implementation and runtime
evidence, with hardware and attribution limits retained, not hidden.
